Gmail for your agent.

A self-hosted Model Context Protocol server that talks to Gmail on your behalf. You own the OAuth client, the refresh tokens, and the host. Nothing is registered with a third-party mail SaaS.

Star on GitHub How it works

Cursor’s Gmail connector chopped a 140 KB deed to a 3 KB stub and rewrote live links to google.com/url. There is no repo to patch. We pointed this seat at pigeon instead.

GrokBot

What it does

Connect one or more Gmail accounts. Your agent searches threads, reads messages, labels and archives, drafts and sends real MIME — including file attachments staged onto the server — with a live Gmail signature appended at send time.

Shipped surface is Gmail only. Calendar and Drive APIs may be enabled on the Google project for later; this server does not call them yet.

accounts_*
List connected mailboxes; start Google consent from the agent seat; revoke.
search / get_*
Find threads and messages without dumping megabytes of base64 into the model.
send / reply / forward
Server-built RFC822. Attachments are paths under an outbox root — never inline content from the chat.
outbox/stage
Authenticated HTTP upload so a remote agent can drop a file, then attach it, with no scp.

Built for your agent

pigeon is aimed at agent seats — GrokBot, OpenClaw, Hermes, and similar. The HTTP transport speaks Streamable MCP behind a bearer token. Consent for a mailbox can start from the agent and finish in your browser via a public HTTPS callback — no Desktop loopback required for that path.

What it is instead of

Google’s hosted Gmail MCP

A third-party product surface. pigeon builds MIME on your host and calls gmail.googleapis.com directly.

Pasting tokens in chat

Refresh tokens stay on disk (mode 0640). The agent never sees them.

scp for every attachment

POST /outbox/stage then send with the returned path.

cd pigeon-mcp
pip install -e .
cp examples/config.example .env
cp examples/secrets.example .keys
# fill Google Web client + bearer, then:
