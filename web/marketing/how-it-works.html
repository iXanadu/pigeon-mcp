Self-hosted Gmail for agents

How it works

Four surfaces: Google OAuth you own, an MCP HTTP endpoint, a stage upload for files, and Gmail itself.

  1. 1

    You create the Google OAuth client

    Web application client, redirect https://<your-host>/oauth/callback. Publish the consent screen to In production (Testing refresh tokens die in seven days). Details in the OAuth guide.

  2. 2

    The agent connects a mailbox

    The agent calls accounts_auth_start, you open the returned URL, Allow the account. Tokens land on the server as gmail-token-*.json.

  3. 3

    Day-to-day mail over MCP

    Search, read, label, draft, send. HTTP requires Authorization: Bearer …. Account address is an argument on every mail tool.

  4. 4

    Attachments without scp

    Agent POSTs bytes to /outbox/stage (same bearer), gets a path under the outbox root, then passes that path to send / reply / forward.

Public routes (typical gateway)

/mcp Streamable MCP — bearer required
/oauth/callback Google redirect — state + PKCE, no bearer
/outbox/stage Upload for later attach — bearer required
/healthz Unauthenticated liveness on the app bind (deploy verifies); gateway should proxy it publicly
/privacy · /terms Consent-screen URLs

Where files live

Outbox and download roots are configurable. On a personal host, /tmp/… with 0700 self-heal on start is fine for transient staging. Tokens stay next to the service (or under a swept prod tree) — never in the agent transcript.
